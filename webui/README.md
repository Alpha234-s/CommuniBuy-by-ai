# CommuniBuy Vue 前端

面向社区场景的团购网站前端，使用 Vue 3、TypeScript、Vue Router、Element Plus、Axios、Pinia、ECharts 和 Vite。

这版页面由本次前端开发生成，替换了原社区二手交易演示页。实际业务数据来自后端；**没有内置演示商品、模拟登录或假支付成功逻辑**。浏览器测试中的测试数据仅由测试程序拦截请求提供。

## 视觉与页面结构

按反馈恢复为参考视觉指南之前的绿色版本：顶部品牌与导航、大幅主题横幅、商品区搜索、分类筛选和较宽的商品卡片；登录、详情和全站字体、圆角、间距同步恢复。保留森林绿、米白和浅橄榄配色，以及社区团购平台名称。

搜索词仍保存在首页 URL 的 q 参数中，后端使用原 keyword 筛选契约。商品列表恢复每页 8 条，电脑四列、中等屏幕三列、手机两列、极窄屏幕一列。商品图标根据接口返回的分类名称对应，不再按商品编号轮换；未知分类使用购物袋。图标仅为分类示意，不代表实际商品照片，也不会在后台创建分类。页面不增加没有后端依据的优惠、销量或配送承诺。

`npm run preview:design` 使用独立浏览器和仅用于截图的示例响应，生成首页、详情、登录页的电脑/手机截图，保存在忽略的 `test-results/design-restored/`。脚本不会注册账号或写入后端，示例数据不会加入正式应用；需要与浏览器测试相同的 Edge/Chromium 环境。

## 开始运行

在 PowerShell 中进入前端目录：

```powershell
cd C:\Users\Lenovo\CommuniBuy-by-ai\webui
npm ci
npm run dev
```

已有依赖且锁文件未改变时，可以直接 `npm run dev`。访问终端给出的本机地址，默认是 `http://127.0.0.1:5173`。先显示登录页属于正常行为：当前后端要求登录后才能查看商品、分类和购物车。

Node 需满足 Vite 实际要求 `^20.19.0 || >=22.12.0`。本次环境使用 Node `v24.21.0`，依赖精确版本以 `package-lock.json` 为准。npm 缓存保存在本目录 `.npm-cache/`。

## 后端地址确认后配置

首次配置可将 `.env.example` 复制为 `.env.local`，已有该文件时直接编辑，不要覆盖自己的配置。配置改变后需重启 Vite。

- `VITE_API_BASE_URL` 默认 `/api/v1`，是浏览器调用的业务根路径。
- `API_PROXY_TARGET` 仅开发时使用，填写团队提供的后端源地址，格式是协议、主机和端口，**不含 `/api/v1`**。Vite 代理保留原 API 路径。
- 本机浏览器通过 Vite 同源访问 `/api`；开发代理转发时移除与当前 Vite 请求 Host 一致的本机 Origin，避免将服务器代理请求误判为跨源浏览器请求。其他来源的 Origin 保留，后端 CORS 检查继续生效。此行为只用于开发代理，部署仍需配置正式反向代理或精确 CORS。
- `.env.example` 中被注释的地址只是格式示例，不代表已经确认或启动的后端。
- 若浏览器直接跨源访问后端，后端需要明确允许前端完整 origin。`localhost` 与 `127.0.0.1` 不同。
- 不要将 JWT 签名密钥、数据库密码或模拟渠道签名密钥写入任何 `VITE_` 变量。

没有服务地址时可以查看登录、注册、错误页面的界面，无法凭空登录或展示实际商品。登录失败会明确显示连接或接口错误，不会回退到假账号。

## 关键业务规则

- 金额使用整数分，ID/版本保留准确十进制字符串。使用 `lossless-json` 从响应原文开始解析，大整数出站使用 BigInt 和无损序列化，不把已舍入的 Number 转为字符串补救。
- 多商品订单展示 `lines`，订单总额使用后端 `total`，不使用主表摘要单价乘总数量。
- 历史快照缺失时如实显示，不用当前商品名伪装历史成交信息。
- 单商品下单和购物车结算保存账号隔离的请求快照及幂等键。超时后重试保持原参数；checkout 保持原 `cartVersion`，即使服务端已经清空购物车。
- 修改库存发送读取时的版本。409 后需要重新读取并人工核对，前端不会替换版本自动重发旧库存。
- 待支付订单卖家地址不可见；前端不绕过权限读取买家个人资料。
- 401 失效令牌清除并回登录；403 保留身份但提示无权；409 显示业务冲突；429 遵守 Retry-After，不自动重复写入。
- 没有 refresh-token 接口，不虚构刷新机制。令牌保存在当前标签页 sessionStorage，不存密码。401 后保留账号隔离的待确认意图以便重新登录核对；明确退出/改密会清除该账号的本地意图。
- 付款必须由后端显式启用 SIMULATOR。页面不接触渠道密钥，不调用渠道 notify 接口，不涉及真实资金。

## 后端尚需补充的入口

这些是已知限制，不能当作完整功能已验收：

1. 退款仅有按编号读取，缺少可发现待审核申请的退款列表/按订单查询；OrderView 也没有 refundId 和完整处理中摘要。当前提供申请后详情及已知编号查询，无法凭前端实现跨设备售后队列。
2. 已发货/完成后如何按订单获取支付记录编号，以及历史结算批次列表，仍需后端补契约。
3. 订单级“哪些商品已经评价”查询未提供；重复评价由后端拒绝，前端不靠本地标记冒充永久状态。
4. 没有商品图片字段/上传、多地址簿、SKU、物流运单、部分退款、真实支付或趋势统计接口。本版不虚构这些功能。

商品插图是本地 HTML/CSS 与图标组成的统一占位示意，页面已标注。不会请求外部图片服务。

## 检查和测试

```powershell
npm run typecheck
npm test
npm run test:e2e
npm run build-all
npm run format:check
```

- 单元测试验证整数金额、Long/BigInteger JSON 精度、时间边界、权限、幂等意图、Bearer、401 和 Retry-After。
- 浏览器测试通过 Playwright 拦截测试请求，验证登录、权限、多商品订单、模拟支付、丢响应重试、库存冲突、后台及窄屏行为。**测试通过不等于已完成真实后端联调**。
- 浏览器测试独立启动/关闭内存中的 Vite 服务，使用端口 4179。Windows 优先使用已安装的 Edge；其他环境需先准备 Playwright Chromium。
- 若需把浏览器安装在前端目录内，可在同一 PowerShell 会话先设置 `$env:PLAYWRIGHT_BROWSERS_PATH="$PWD/.playwright-browsers"`，再执行 `npx playwright install chromium` 和 `npm run test:e2e`。
- 截图与失败 trace 写在忽略的 `test-results/`。测试账号和商品仅为测试数据，不发往真实后端。
- `npm run format` 统一格式。不要手工修改 lock 文件或将缓存、构建产物、测试截图提交。

## 构建和交接

- `npm run build`：普通网站产物 `dist/`，按路由拆包。
- `npm run build-single`：单 HTML 产物 `dist-single/index.html`，使用 hash 路由。仍需可用 API，不代表可脱离后端离线完成交易。
- 普通网站默认 history 路由，部署方需要页面路径回退 index.html；`/api` 不能回退 HTML，需要单独转发后端。无法提供回退时可设置 `VITE_ROUTER_MODE=hash` 后构建。
- 大量 Element Plus 组件和图表会产生较大构建块；图表已仅在后台按需加载。上线前可继续按团队性能目标优化。
- 根目录 CI/Nginx/后端配置不在本次修改范围。团队后续可在 CI 使用上述检查命令，在部署环境配置同源 API 和 HTTPS。
