# 社区团购平台后端设计方案

## 1. 项目概述
本项目是一个社区团购平台的后端系统，旨在支持社区居民下单、团长管理、商品管理及订单处理等核心业务流程。

### A. 核心功能需求分析
一个完整的社区团购后端需要支撑以下核心业务流程：
* **用户与权限系统**：支持用户注册、登录（手机号/微信）、角色划分（用户、管理员）以及收货地址管理。
* **商品与库存管理**：商品分类、详情展示、以及关键的**团购库存控制**（防止超卖）。
* **团购活动管理**：支持增查改删、定时开启/结束的团购活动，管理团购状态。
* **订单与支付流程**：实现从“下单 -> 校验库存 -> 锁定库存 -> 支付 -> 状态流转”的完整闭环。
* **平台管理**：查看管理用户、订单，统计收益...

## 2. 核心功能模块设计
根据“社区团购”业务逻辑，后端需要实现以下核心功能：

### A. 用户与权限管理 (User & Auth)
- **用户注册/登录**: 只支持用户id+密码登录。
- **角色管理**: 区分普通用户 (User)、管理员 (Admin)。
- **管理功能**: 用户可发起/参与团购，编辑自己发布的团购、查看自己的订单、管理自己的收货地址、统计自己的收益/支出。管理员可按用户或全局查看和修改所有用户信息、订单、团购。

### B. 商品管理 (Product Management)
- **商品列表**: 支持分类查询、搜索。
- **商品详情**: 商品规格、价格、库存、详情描述。
- **库存控制**: 团购开始前的库存预留与下单时的实时扣减。

### C. 团购/拼团管理 (Group Buying/Flash Sale)
- **团购活动创建**: 发起团购、修改、关闭、删除。
- **团购状态控制**: status为负表示下架，>=0表示上架且已发货n次，上架时使用时间判断是否未开始/进行中/结束

### D. 订单管理 (Order Management)
- **下单流程**: 校验库存 -> 创建订单 -> 锁定库存 -> 支付（模拟，始终成功）。
- **订单状态流转**: 待支付 -> 待发货 -> 待收货 -> 已完成/已关闭。
- **订单查询**: 用户查看自己的订单、自己发起的团购的，管理员查看所以订单列表。

## 3. 建议目录结构 (Server-side)
基于 Java (Gradle) 项目结构建议：

```text
server/app/src/main/java/hy/communibuy/
├── config/             # 配置类 (如 Spring Security, Swagger, MyBatis 配置)
├── controller/        # 控制层 (处理 HTTP 请求，负责参数校验)
├── service/           # 业务逻辑层 (定义接口)
│   └── impl/          # 业务逻辑实现类
├── repository/        # 数据访问层 (DAO，负责与数据库交互)
├── entity/            # 数据库实体类 (与数据库表一一对应)
├── dto/               # 数据传输对象 (Request/Response 对象，避免直接暴露 Entity)
├── exception/         # 全局异常处理类
└── utils/             # 通用工具类 (日期、字符串、加密编码等)
```

## 4. API 接口设计 (RESTful)

### 用户模块 (User & Auth API)
- `POST /api/v1/auth` - 用户登录
- `POST /api/v1/auth/logout` - 用户登出
- `POST /api/v1/auth/register` - 用户注册
- `POST /api/v1/auth/reset` - 修改密码
- `GET /api/v1/user` - 获取当前用户id
- `GET /api/v1/user/{id}` - 获取用户信息（昵称、描述、地址）
- `POST /api/v1/user/{id}` - 修改用户信息
- `GET /api/v1/users` - 获取所以用户id

### 商品（团购）模块 (Item API)
- （在社区团购体系中，商品即发起的团购）
- `GET /api/v1/item` - 分页查询团购id列表
- `POST /api/v1/item` - 创建新团购
- `GET /api/v1/item/{id}` - 获取团购详情
- `POST /api/v1/item/{id}` - 管理团购（修改内容、状态更变、删除）

### 订单模块 (Order API)
- `GET /api/v1/order` - 获取订单id列表
- `POST /api/v1/order` - 创建订单
- `GET /api/v1/order/{id}` - 获取订单详情
- `POST /api/v1/order/{id}` - 修改订单信息（只能改地址）

## 5. 技术栈建议
- **框架**: Spring Boot (推荐)
- **数据库**: MySQL
- **缓存**: Redis (用于库存预扣和 Session)
- **持久层**: MyBatis Plus 或 Spring Data JPA
- **文档**: SpringDoc / Swagger
