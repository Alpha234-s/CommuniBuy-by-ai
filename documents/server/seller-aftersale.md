# 卖家售后发现入口

任务：补齐买家申请后，卖家能自行查询申请并进入已有详情/审核接口的闭环。
负责人：本次编码助手；独立维护者评审待进行。范围仅后端、测试和接口文档，不修改 webui。

基线：团队 main@7f4da28 已包含后端与 Vue 前端，故本任务从该提交建立 feat/seller-aftersale-inbox，不从缺少前端的旧分支重做功能。

## 需求与验收

- 默认售后列表只返回当前登录用户销售订单的申请；买家视角仅返回自己的申请，管理员可显式查看全局。
- 分页、状态及订单筛选共同生效，不接收可绕过权限范围的用户/卖家身份参数。
- 买家、对应卖家及管理员可按订单获取售后；无申请返回成功且 data=null，无权用户仍返回403。
- 卖家通过自己的列表取得编号，再调用已有详情、approve/reject/retry，无需买家传递编号。
- 不改资金/库存/状态流转与历史迁移，不引入消息队列或实时推送。前端进入页面/刷新时查询列表即可发现持久化申请。
- HTTP回归须覆盖买家提交→卖家独立查询→详情→审核→买家查看结果，以及跨卖家隔离、管理员权限、筛选分页、无申请及非法参数。

## 前端接入

1. 卖家工作台请求 `GET /api/v1/refunds?status=REQUESTED&page=0&size=20`，用返回的 content 展示待处理记录、count 展示总数。
2. 点击记录中的 id 进入现有 `/refunds/{id}` 页面，复用审核操作。
3. 订单详情请求 `GET /api/v1/order/{id}/refunds`，有记录则显示状态及查看售后按钮，不再要求手工输入编号。
4. 买家售后列表使用 `scope=buyer`，管理员全局管理使用 `scope=all`。
5. 申请进度取 refunds 的真实状态，不用订单现有 refundStatus（结算结果）推测是否待审核。全部编号/金额继续使用现有无损JSON解析。
